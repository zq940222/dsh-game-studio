# Role index

Generated by the port from the 49 role briefs. Do not hand-edit — fix the
upstream role brief or the port rules and re-run `port.mjs`.

- `accessibility-specialist` (tier 3, engineering) — The Accessibility Specialist ensures the game is playable by the widest possible audience.
- `ai-programmer` (tier 3, engineering) — The AI Programmer implements game AI systems: behavior trees, state machines, pathfinding, perception systems, decision-making, and NPC behavior.
- `analytics-engineer` (tier 3, engineering) — The Analytics Engineer designs telemetry systems, player behavior tracking, A/B test frameworks, and data analysis pipelines.
- `art-director` (tier 2, art) — The Art Director owns the visual identity of the game: style guides, art bible, asset standards, color palettes, UI/UX visual design, and the art production pipeline.
- `audio-director` (tier 2, audio) — The Audio Director owns the sonic identity of the game: music direction, sound design philosophy, audio implementation strategy, and mix balance.
- `community-manager` (tier 3, production) — The community manager owns player-facing communication: patch notes, social media posts, community updates, player feedback collection, bug report triage from players, and crisis communication.
- `creative-director` (tier 1, leadership) — The Creative Director is the highest-level creative authority for the project.
- `devops-engineer` (tier 3, engineering) — The DevOps Engineer maintains build pipelines, CI/CD configuration, version control workflow, and deployment infrastructure.
- `economy-designer` (tier 3, design) — The Economy Designer specializes in resource economies, loot systems, progression curves, and in-game market design.
- `engine-programmer` (tier 3, engineering) — The Engine Programmer works on core engine systems: rendering pipeline, physics, memory management, resource loading, scene management, and core framework code.
- `game-designer` (tier 2, design) — The Game Designer owns the mechanical and systems design of the game.
- `gameplay-programmer` (tier 3, engineering) — The Gameplay Programmer implements game mechanics, player systems, combat, and interactive features as code.
- `godot-csharp-specialist` (tier 3, engineering) — The Godot C# specialist owns all C# code quality in Godot 4 projects: .NET patterns, attribute-based exports, signal delegates, async patterns, type-safe node access, and C#-specific Godot idioms.
- `godot-gdextension-specialist` (tier 3, engineering) — The GDExtension specialist owns all native code integration with Godot: GDExtension API, C/C++/Rust bindings (godot-cpp, godot-rust), native performance optimization, custom node types, and the GDScript/native boundary.
- `godot-gdscript-specialist` (tier 3, engineering) — The GDScript specialist owns all GDScript code quality: static typing enforcement, design patterns, signal architecture, coroutine patterns, performance optimization, and GDScript-specific idioms.
- `godot-shader-specialist` (tier 3, engineering) — The Godot Shader specialist owns all Godot rendering customization: Godot shading language, visual shaders, material setup, particle shaders, post-processing, and rendering performance.
- `godot-specialist` (tier 3, engineering) — The Godot Engine Specialist is the authority on all Godot-specific patterns, APIs, and optimization techniques.
- `lead-programmer` (tier 2, engineering) — The Lead Programmer owns code-level architecture, coding standards, code review, and the assignment of programming work to specialist programmers.
- `level-designer` (tier 3, design) — The Level Designer creates spatial designs, encounter layouts, pacing plans, and environmental storytelling guides for game levels and areas.
- `live-ops-designer` (tier 3, design) — The live-ops designer owns post-launch content strategy: seasonal events, battle passes, content cadence, player retention mechanics, live service economy, and engagement analytics.
- `localization-lead` (tier 2, production) — Owns internationalization architecture, string management, locale testing, and translation pipeline.
- `narrative-director` (tier 2, narrative) — The Narrative Director owns story architecture, world-building, character design, and dialogue strategy.
- `network-programmer` (tier 3, engineering) — The Network Programmer implements multiplayer networking: state replication, lag compensation, matchmaking, and network protocol design.
- `performance-analyst` (tier 3, production) — The Performance Analyst profiles game performance, identifies bottlenecks, recommends optimizations, and tracks performance metrics over time.
- `producer` (tier 1, leadership) — The Producer manages all production concerns: sprint planning, milestone tracking, risk management, scope negotiation, and cross-department coordination.
- `prototyper` (tier 3, production) — Prototyping specialist.
- `qa-lead` (tier 2, qa) — The QA Lead owns test strategy, bug triage, release quality gates, and testing process design.
- `qa-tester` (tier 3, qa) — The QA Tester writes detailed test cases, bug reports, and test checklists.
- `release-manager` (tier 2, production) — Owns the release pipeline: certification checklists, store submissions, platform requirements, version numbering, and release-day coordination.
- `security-engineer` (tier 3, engineering) — The Security Engineer protects the game from cheating, exploits, and data breaches.
- `sound-designer` (tier 3, audio) — The Sound Designer creates detailed specifications for sound effects, documents audio events, and defines mixing parameters.
- `systems-designer` (tier 3, design) — The Systems Designer creates detailed mechanical designs for specific game subsystems -- combat formulas, progression curves, crafting recipes, status effect interactions.
- `technical-artist` (tier 3, art) — The Technical Artist bridges art and engineering: shaders, VFX, rendering optimization, art pipeline tools, and performance profiling for visual systems.
- `technical-director` (tier 1, leadership) — The Technical Director owns all high-level technical decisions including engine architecture, technology choices, performance strategy, and technical risk management.
- `tools-programmer` (tier 3, engineering) — The Tools Programmer builds internal development tools: editor extensions, content authoring tools, debug utilities, and pipeline automation.
- `ue-blueprint-specialist` (tier 3, engineering) — The Blueprint specialist owns Blueprint architecture decisions, Blueprint/C++ boundary guidelines, Blueprint optimization, and ensures Blueprint graphs stay maintainable and performant.
- `ue-gas-specialist` (tier 3, engineering) — The Gameplay Ability System specialist owns all GAS implementation: abilities, gameplay effects, attribute sets, gameplay tags, ability tasks, and GAS prediction.
- `ue-replication-specialist` (tier 3, engineering) — The UE Replication specialist owns all Unreal networking: property replication, RPCs, client prediction, relevancy, net serialization, and bandwidth optimization.
- `ue-umg-specialist` (tier 3, engineering) — The UMG/CommonUI specialist owns all Unreal UI implementation: widget hierarchy, data binding, CommonUI input routing, widget styling, and UI optimization.
- `ui-programmer` (tier 3, engineering) — The UI Programmer implements user interface systems: menus, HUDs, inventory screens, dialogue boxes, and UI framework code.
- `unity-addressables-specialist` (tier 3, engineering) — The Addressables specialist owns all Unity asset management: Addressable groups, asset loading/unloading, memory management, content catalogs, remote content delivery, and asset bundle optimization.
- `unity-dots-specialist` (tier 3, engineering) — The DOTS/ECS specialist owns all Unity Data-Oriented Technology Stack implementation: Entity Component System architecture, Jobs system, Burst compiler optimization, hybrid renderer, and DOTS-based gameplay systems.
- `unity-shader-specialist` (tier 3, engineering) — The Unity Shader/VFX specialist owns all Unity rendering customization: Shader Graph, custom HLSL shaders, VFX Graph, render pipeline customization (URP/HDRP), post-processing, and visual effects optimization.
- `unity-specialist` (tier 3, engineering) — The Unity Engine Specialist is the authority on all Unity-specific patterns, APIs, and optimization techniques.
- `unity-ui-specialist` (tier 3, engineering) — The Unity UI specialist owns all Unity UI implementation: UI Toolkit (UXML/USS), UGUI (Canvas), data binding, runtime UI performance, input handling, and cross-platform UI adaptation.
- `unreal-specialist` (tier 3, engineering) — The Unreal Engine Specialist is the authority on all Unreal-specific patterns, APIs, and optimization techniques.
- `ux-designer` (tier 3, design) — The UX Designer owns user experience flows, interaction design, accessibility, information architecture, and input handling design.
- `world-builder` (tier 3, production) — The World Builder designs detailed world lore: factions, cultures, history, geography, ecology, and the rules that govern the game world.
- `writer` (tier 3, narrative) — The Writer creates dialogue, lore entries, item descriptions, environmental text, and all player-facing written content.
